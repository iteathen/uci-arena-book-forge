# Preserve operator resource and analysis settings through refresh

An installed Book Forge instance with validated resource and analysis overrides lost those settings when Installer refreshed a saved credential locator. The producer renderer rebuilt only workspace, Stockfish and credential references. Returning to the default reserve made the service unable to acquire or analyze on the available disk, despite the operator configuration passing normal validation.

This affects B-O2 and targets B-T7/B-T8/B-T9. Premise B-P4 requires real resource admission and truthful reporting; keeping a setting through deployment must not bypass that admission, change foreground priority or grant strength authority. The target is durable, validated operator tuning under current execution bindings. Credential secrecy, exact component ownership and native/resource gates remain hard constraints, not tradeoffs.

Candidates: leave manual post-refresh edits as an operational workaround (rejected because refresh repeats the defect and verification reports drift); lower global defaults (rejected because it changes every machine and loses operator choices); preserve arbitrary prior configuration (rejected because it retains obsolete executable/helper/policy/credential bindings); preserve only validated producer-owned resource and analysis settings while recomposing current bindings (selected). No setting is invented or broadened by the renderer.

The renderer admits one bounded stable regular configuration file with no linked ancestors, strict UTF-8/JSON and before/after descriptor/path identity checks. The existing complete configuration validator admits every field before the two explicit tuning sections are copied. File and installer composition now share the same synchronous validator; the normal async loader keeps its Node-version check and field/path behavior. Invalid retained policy fails rather than being discarded. Credentials remain path references and their contents are never opened during rendering.

TDD: six regressions failed before implementation; all seven new cases and two existing integration tests pass. Cases include preservation with current dependency/credential rebinding, invalid numeric/unknown policy, zero reserve, oversized input and a linked directory. A nonauthor reviewer independently inspected the complete four-file implementation and ran all nine cases without a substantive blocker.

Native helpers were freshly built from the locked vendored source using Visual Studio 18 2026/MSVC 19.50.35730 and SDK 10.0.26100.0 before the Windows tests. The first parallel full run failed one current-process identity probe; the isolated case passed and a serial full run passed 176/177 tests with one explicit immutable-0.4.4 lifecycle-clone skip. No identity timeout, guard or test assertion was weakened. Vendor-lock, repository-boundary, automation and whitespace checks pass. Version 0.4.11 prepares a distinct candidate identity; hosted exact-head CI, signed packaging and actual installed refresh/service acceptance remain separate gates.

This repair neither qualifies the existing integration book for strength nor repairs the independently observed shared-resource lease issue. Those findings and historical snapshots remain retained for follow-up work.
